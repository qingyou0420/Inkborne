## 〇、结论（先读这里）

1. **P0 可以收口，前提是合入本 PR 的四处最小修复。** 方案「七·P0」PR-1 的 8 项与 PR-2 的 5 项在 `packages/core/src/authoring`、`packages/studio/src` 全部按意图落地：字段级 diff（`canonFieldDiff`，`openQuestions` 不比）、`ask.review` 分诊槽（按分类 ≤60 条 / 章概要 50 章分批，索引式提示词，`target` 不在索引进 `unmapped`）、按批启发式降级（名称 / 别名 / 新 token / 约束类）、影响索引 `story/workflow/impact/<id>.json` + 两份标准审查报告、三条关闭规则（研墨采用比 artifactId、织卷采用比 `title+summary` hash、`resolve` 手动）、三条路由（`/impact/recompute`、`/impact/resolve`、`GET /impact/:id`）、研墨 / 织卷「需核对 N · 全部 M」默认视图与预勾、落笔可点黄条、本书页合成一行、问心两段 toast。对照表见「一」：13 项中 11 项**通过**、2 项**通过·备注**、0 项**未通过**。
2. **发现一处真正会让黄条永不消的死锁，已修（F1）。** 分诊降级为空报告（`degraded`）时，`syncImpactWatches` 因 `openCount` 为 0 立刻把两条 watch 置 `acknowledged=true` 并把 `impactBaseline` 前移到新版；随后「重算」因 `from === to` 走 `unchanged` 分支直接返回、不取代旧报告，「标为已核对」也无项可关——而落笔黄条与本书页「等你过目」读的是报告的 `degraded` 字段，于是**永远显示「影响分辨失败，可重算」且两个按钮都无效**。现改为：降级空报告本身就是那条「粗提醒」，watch 保持未确认、基线不动（「重算」因此真的会再分诊一次），只有作者点「标为已核对 / 忽略」才确认并前移基线；UI 侧降级横幅在其 watch 已确认后不再显示。有核心测试与纯函数测试覆盖。
3. **另修两处死链（F2、F3）与一处基线 CI 红灯（F4）。** F2：分诊 run 在写出报告前失败（如 `ask.review` 槽配置无效、Studio 重启回收为孤儿 run）会让 watch 卡在 `impactReportId: "pending"`，而 UI 既不把它当遗留提醒、`BookStudy` 又把带「正典」字样的 watch 折进影响行——结果**提醒彻底消失、watch 却永远未确认**；现把 `pending` 视同遗留，落笔 / 本书页给「上游正典有过变更，尚未分辨影响」+ [重算] [标为已核对]。F3：织卷对 `weave:structure` 项「按意见修订」打开的是「重新规划分卷」对话框，但请求仍发 `reviseStructure: isStructureCandidate`（有章概要的规划为 `false`），实际跑的是按卷范围修章概要，采用还会被 `validateVolumePlan` 拒绝；改为 `reviseStructure: generation.mode === "structure"`。F4：`PRODUCT_VERSION` 仍是 `2.2.7` 而 #138 把根 `package.json` 提到 `2.2.8`，`branding-chrome.test.ts` 在基线上就红，#140 / #141 的 CI 均为 failure；对齐为 `2.2.8`。这与 P0 无关，但方案 8.3 的合入门槛是「全绿」。
4. **不阻塞收口、建议合成一个 follow-up PR 的补丁清单见「四」，共 8 条，每条 ≤ 30 行。** 最值得先做的两条：① 分诊是后台 run，但研墨 / 织卷 / 落笔 / 本书页只在自己发起时才跟踪它——作者从问心采用后直接切到研墨，页面不会自动出现「需核对」筛选，落笔黄条会停在「正在分辨…」直到任意一次 refetch；② `globals`（文风 / 篇幅 / 书名改动、以及「改动可能是全局性的，建议按影响重新生成」的 60% 提示）在 UI 任何位置都没有渲染，方案 2.3 / 4.2 要求在摘要里说明。其余为边角：本书页降级 / 遗留行缺「标为已核对」、`ground:catalog` 项混进研墨审查报告会让整批修订被 `unavailable-target` 挡住、`closeImpactItems` 在采用末尾未包非致命、「审查所选」未附 reason、`unchanged` 不确认未决 watch、已确认 canon watch 每轮累积两条。
5. **验证：** `pnpm typecheck` 通过（core `tsc` build + studio client / server `tsc --noEmit`）。CI `pnpm test` 所列 core 22 个文件 333 例全绿（含 `authoring-impact.test.ts` 由 10 例增至 12 例）；studio 52 个文件 491 例全绿（修 F4 前唯一红灯是 `branding-chrome`，与本轮无关）。真模型下的分诊质量（方案 8.1「醉词」数量级）按方案属于收口后由作者实机确认，本文不替代；实机若发现 `affected` 漏项，按方案优先调 `triagePrompt` 与 `CLIP_ENTRY / CLIP_SUMMARY`，不放宽到全量。

### 2.1 会让黄条永不消 / 死链（本 PR 已修，详见「三」）

### 2.2 不阻塞收口的缺口（进 follow-up，见「四」）

- **后台分诊完成后页面不自动刷新。** `useApi` 的失效事件按完整 URL 匹配，`/authoring/workspace?bookId=…` 不会被 `/authoring/impact/*` 的 POST 失效；研墨 / 织卷 / 落笔 / 本书页只在自己 `setActiveRunId` 时才 `useAuthoringRun`。作者在问心采用后立刻切到研墨：看到的是「全部 157」无筛选；落笔黄条停在「正在分辨正典改动的影响…」直到任意操作触发 `refetch`。问心页停留则正常（toast 第二段 + `refetch`）。
- **`globals` 无处展示。** `voice / chapterWordCount / title / genre` 改动的说明、以及 4.2 的「改动可能是全局性的，建议按影响重新生成所选」都只在 `impact.globals` 里；`impactWorkspaceSummary` 有返回，但 `rg globals packages/studio/src` 只命中类型定义。方案 2.3 要求「记为 globals 在报告摘要里说明」。
- **本书页 degraded / legacy 行缺「标为已核对」。** 只有落笔黄条有；作者若还没到落笔阶段（研墨中），要清掉这两种提醒只能去落笔页。
- **`ground:catalog` 混进研墨审查报告。** `reviewIssues` 把它写成 `target:"catalog"` 的 issue；抽屉里勾上它会让 `groundRevisionScope` 整批返回 `unavailable-target`。
- **`closeImpactItems` 未包非致命。** `adoptGroundEntries / adoptWeave` 末尾直接 `await`，`impact/*.json` 若被手改坏，采用会在 `canon.md / volume_map.md / manifest` 已写入后抛错。
- **「审查所选」未附 reason**（方案 6.2）。需要 `reviewGroundEntries` 加 `requirements`。审查上下文已含新正典，所以模型实际上仍是「对照新正典」在审。
- **`unchanged` 分支不确认未决 watch。** 遗留 watch（升级前因「同内容重采用」误触发的）点「重算」→ `from`（首个已采用版）与 `to` 内容相同 → run 完成「正典内容未变」，但横幅不消，需再点「标为已核对」。
- **已确认 canon watch 累积。** `upsertCanonWatches` 的 `keep` 保留 `acknowledged` 的 canon watch，每轮采用 + 归零后 manifest 多两条；UI 跳过已确认项，无可见影响。
- **织卷两处范围边角。** 「按影响重新生成所选」用 open 章 min–max 调 `/weave/generate`，会重写中间未受影响章（方案 6.3 只对「按意见修订」规定了 min–max）；节点面板对 `range:a-b` 节点未传 `endChapter`。
- **纯 `targetChapters` / `genre` 改动也跑 4 次 LLM。** `MAPPABLE_FIELDS` 含两者；硬规则已覆盖 `targetChapters`，LLM 批次多为空返回。P1 调优。
- **研墨面板把分诊 run 的 `partial`（作者取消）当「有条目没有生成成功」。** 文案错位，不影响数据。
