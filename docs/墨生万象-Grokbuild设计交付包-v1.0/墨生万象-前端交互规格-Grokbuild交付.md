# 墨生万象 · 四 Agent 前端交互规格

设计版本：1.0 · 2026-09-08。用途：交给 Grokbuild 实施的设计依据。

本交付包含静态页面设计与交互定义，未实现前端、接口或核心 Agent。PDF 中按钮不可点击，任务进度、模型别名和小说内容都是演示数据。本文规定目标行为，不代表当前程序已有这些能力。

配套文件：`墨生万象-前端页面设计稿.pdf`（S01-S12）、`墨生万象-四Agent协作重构规划.md`（代码审查与架构）、`Grokbuild-开工说明.md`（实施入口）。

仓库基线：[qingyou0420/Inkborne，4d0c0f5](https://github.com/qingyou0420/Inkborne/tree/4d0c0f5a53e733bace887e4169c15015a21ac482)。实施前核对当前分支变化。既有代码事实以配套重构规划的源码链接为据；本文新增界面与交互均为设计决策。

## 1. 目标与边界

让一个人在本地完成一本小说：与问心讨论，采用正典并建书；用研墨建立设定；用织卷规划卷纲和每章概要；在落笔中写作、修改与采用正文。作者可随时回看前一步。四步通过明确采用的资料协作，各自保留会话、要求和运行记录。

四个主 Agent 分别负责产出，各自的审查角色只阅读、判断和提出建议。生成结束后由用户决定是否审查；审查后可以选择意见，交回主 Agent 修改。允许未经审查直接采用。

保留现有 Electron 桌面程序、React Studio、Hono、本地文件和 InkOS 能力。沿用书架、编辑器、模型服务库、历史与导出。首轮覆盖长篇创作四步。短篇及其他已有工具保留原入口与行为，后续另行接入。

个人用途无需组织权限、团队审批、计费、运营后台或强制质量评分。必要的工程重点是稿件不丢、版本能分清、模型配置真实生效、失败可恢复。

## 2. 信息架构与主路径

全局侧栏保留墨生万象标志、书架、当前作品、问心记录、模型配置、项目设置。上方是书房入口、当前作品名和问心 / 研墨 / 织卷 / 落笔四步切换。当前书名过长时截断，悬停显示完整名称。

- 书架：沿用现有列表与打开书籍方式；“新建作品”进入问心的新书构思。允许直接粘贴已有正典形成候选，不要求先完成聊天问答。
- 新书构思：拥有独立 draftId 和持久化会话，采用正典前不算正式书籍。问心记录可重新打开尚未建书的构思。
- 书房 S01：回到上次编辑位置，浏览四步成果与需要核对的变化。
- 问心 S02：对话、正典候选、审查、版本历史、采用并建书。
- 研墨 S03：设定目录、条目编辑、生成与批量范围、审查、采用。
- 织卷 S04：全书大纲 / 卷纲 / 章概要树、覆盖数量、范围任务、审查、采用。
- 落笔 S05：章节目录、正文编辑、修改要求、审查与版本。
- 共用 S06/S07：审查侧栏与差异比较，由四步的成果操作打开。
- 设置 S08/S09：八角色配置及当前角色编辑抽屉，服务连接沿用现有管理页。
- S10 是状态组件示例；S11 是窄窗适配；S12 是暗色适配。它们不是额外导航入口。

推荐新书路径：新建作品 → 问心对话 → 生成正典 → 可选审查和修改 → 采用正典并建书 → 生成设定 → 采用需要的条目 → 规划全书及章概要 → 采用规划 → 写第 1 章 → 可选审查和修改 → 采用正文 → 写下一章。

四步导航始终可访问。没有上游资料时显示来源入口和缺少的资料；允许作者补写、导入或明确使用当前已有资料继续。审查分数、待定项和非必要设定不能锁住后续页面。操作至少需要一个可定位目标，例如审查需要非空成果、写章需要章节位置；没有目标时就地提供“添加章节”或“选择成果”。

## 3. 统一视觉规范

### 3.1 品牌与字体

延续仓库“墨·宣·朱”：纸白背景、深墨文字、少量朱色标识、低饱和提醒色。避免把写作区做成密集仪表盘。沿用真实 `inkborne-mark.png`、现有 lucide 图标及本地字体；无需新封面、装饰插画或远程字体。

样式来源：[Studio index.css](https://github.com/qingyou0420/Inkborne/blob/4d0c0f5a53e733bace887e4169c15015a21ac482/packages/studio/src/index.css)。优先复用现有变量，以下为设计对应关系。

- 页面背景：浅色 `oklch(0.975 0.006 85)`，暗色 `oklch(0.17 0.008 260)`。
- 纸面与浮层：浅色 `oklch(0.99 0.004 85)`，暗色 `oklch(0.21 0.009 260)`。
- 正文：浅色 `oklch(0.24 0.012 260)`，暗色 `oklch(0.93 0.010 85)`。
- 主按钮：浅色 `oklch(0.27 0.014 260)` / 字色 `oklch(0.975 0.006 85)`；暗色 `oklch(0.90 0.012 85)` / 字色 `oklch(0.20 0.010 260)`。
- 次要文字：浅色 `oklch(0.50 0.015 260)`，暗色 `oklch(0.70 0.012 85)`。
- 边线：浅色 `oklch(0.88 0.010 85)`，暗色 `oklch(0.30 0.010 260)`。
- 次级底色：浅色 `oklch(0.94 0.010 85)`，暗色 `oklch(0.26 0.010 260)`。
- 朱色文字沿用 seal-text，提示底色沿用 seal-soft；待核对和替换沿用 mark-text / mark-soft；新增内容使用 ok 和浅绿衬底。新增浅绿衬底可用浅色 `oklch(0.95 0.016 160)`、暗色 `oklch(0.25 0.024 160)`，只作差异背景。

页面标题与书名使用现有 serif 字族，优先 LXGW WenKai；操作、说明、表单用现有 sans 字族。正文编辑默认 sans，沿用已有阅读字体设置。PDF 为嵌入字体的静态排版，标题用本机楷体近似，正文用微软雅黑；实施以仓库字体和本文字号为准，避免照搬 PDF 的字形差异。

层级：书房书名 40px；阶段标题 30-32px；成果标题 26-32px；分区标题 16-18px；正文默认 18px / 行高 1.8-1.9；普通说明 14-16px；元信息 12-13px。PDF 个别微型索引为 10-11px，实施统一提升到至少 12px并允许换行。正文可调 16-24px，调整后保持工具可达。

### 3.2 尺寸与布局

PDF 单页 1600×1160，内部主要界面画板为 1440×900，S11 为 1100×900。画板外标题、三条注释和页码属于交付文档，不放入产品界面。画板尺寸是参考视口，不是整个窗口的固定尺寸。

1440px 参考：左栏 176px，顶部导航高 72px，工作区外边距 32px，列间距 24-28px。全局栏和顶部稳定，正文、目录、审查分别滚动。使用 flex/minmax 与实际高度布局，不能复制 PDF 绝对坐标。底部操作栏预留空间，不遮住最后一段正文。

间距使用 4/8/12/16/24/32/48px。工作面板圆角以现有 12px 为基础，紧凑输入/按钮使用 6-8px。按钮常规高度 38-40px，输入最小 42px；主要动作文字明确，使用一个最高强调按钮。列表行通常 40-48px；长标题允许两行，增加行高。

宽度适配：

- 1440px 及以上：默认完整侧栏；问心双栏；研墨和织卷目录加内容；落笔目录加正文。最大可读正文宽度约 800-860px，超宽时居中，不无限拉长行。
- 1200-1439px：全局侧栏可收为 64px，目录可折叠；问心两栏各不少于 420px，空间不足切标签。审查优先覆盖抽屉，不把正文压到 600px 以下。
- 1024-1199px：参照 S11，64px 侧栏，单主栏；问心“对话 / 正典”标签；目录从按钮展开；审查抽屉宽度约 420px，覆盖在内容上；差异比较上下排列。
- 低于 1024px 或高倍缩放：继续单栏退让，收起非必要导航，按钮换行，抽屉接近全宽。常用桌面最低目标 1024×700；不要通过强制窗口下限阻断缩放可访问性。首轮不另做手机专用应用。
- 低高度窗口：标题信息压缩为紧凑行；内容滚动，底栏保留。1600px 以上大屏不增加第四列。

选中导航的底色表示“当前页面”，圆点表示成果状态，二者独立。空心为未开始；实心为有已采用成果且没有新候选/进行任务；朱色小点表示有草稿或任务。悬停/读屏必须提供文字状态；完成覆盖数量在书房和阶段页显示，圆点不表示审查通过。

## 4. 全局行为：成果、保存、任务

### 4.1 三条独立状态线

成果状态：无成果 → 当前工作草稿 → 可采用候选 → 已采用版本。已采用 v2 与新候选 v3 可以同时存在。手工编辑已采用版时形成草稿，不直接改正式依据。

运行状态：未运行 / 生成中 / 暂停请求中 / 已暂停 / 完成 / 部分完成 / 失败 / 已取消 / 连接恢复中。使用真实条目数、章节数或当前步骤，不生成虚假百分比。

审查状态：未审查 / 审查中 / 有报告 / 本次审查失败 / 报告对应旧稿。正文版本未变但参考正典或设定改变时，另外显示“审查依据有更新”；不能把它误写成正文旧稿。

“18 项已采用”和“2 项新草稿”是独立统计，同一设定可同时有正式版和候选版。全书进度分“概要已生成 N/目标数”“概要已采用 M/目标数”，已生成不自动等于已采用。正式正文计数只包括已采用章节。

### 4.2 保存与版本节点

聊天与编辑内容自动保存在本地。编辑停止约 600ms 后保存可变工作草稿；失焦、切换成果、启动审查、生成、采用时立即请求保存。状态依次为“尚未保存 / 保存中 / 草稿已保存 / 保存失败”。仅收到持久化成功后显示已保存。

自动保存的每次敲字不创建历史版本。审查前、生成完成、按意见生成完成、采用前和显式保存版本时创建不可变快照；只有内容实际改变才增加可见版本号。画板 v2/v3/v4 指这些快照。系统可用内部 revision 跟踪草稿，不能混用显示编号。

启动审查时先把草稿保存成被审快照。审查中可继续编辑另一份工作草稿，报告回来后如果正文已变，显示旧稿提示。启动重生成同理保留输入基线；期间发生手改时把模型输出保留为并列候选，提示“生成期间你编辑了草稿，请比较”，不能用迟到输出覆盖用户编辑。

保存失败保留编辑器内容，提供重试和复制/导出；离开作品或关闭程序涉及未保存内容时才提示。普通导航、关闭审查栏、采用可恢复版本不反复弹确认。

### 4.3 长任务与冲突

一本书同一时刻默认运行一个生成/改写任务，正在生成的范围可见。切页不取消任务；全局可见简短任务入口，回到原页恢复进度、输出和滚动位置。按不可变快照做审查可独立进行，不随页面关闭而取消。

同一成果的采用或覆盖写入不能与它的生成保存相互踩踏；需要时就地说明“此条目正在生成，完成后可采用”。其他条目可编辑和读取，短暂文件写入由存储层串行处理。不要把整本书全部操作锁死。

暂停批量任务：点击后显示“正在暂停，已完成部分已保存”，允许当前小步骤完成或中止，停止排下一批；返回“已暂停”。继续时只处理未完成目标。单次生成用“停止生成”，部分文本保存成“未完成草稿”，用户可编辑、继续或重新生成。

重启后根据 runId 恢复实际任务：仍运行则重连；已经停止则显示“任务已中断，已完成内容保留”，提供继续/重试。不能永久停留在转圈，也不能默认声称任务仍在后台。

### 4.4 采用与后续影响

采用更新该范围正式成果，保留被替换版本及来源。成功提示包含下一步，例如“正典已采用，新书已建立”，而非笼统“成功”。采用失败保留候选，正式成果保持原有可读版本。

上游改动只有在采用后才影响下游。新草稿生成和聊天不会让全书变脏。下游显示“依据有更新”，点击列出资料名、原版本、新版本、相关章节；引用信息不足则说明“暂按全书范围提示”，不能装作精确语义分析。

作者可以查看差异、调整有关部分，或“确认仍适用”。确认适用保存一次核对记录，不修改历史生成时的 inputRefs，也不伪造新审查。再次采用新版上游后重新提示。后续生成默认使用最新采用资料；继续沿用旧资料时必须显式显示版本。

## 5. S01 书房

页面重点是接着写：作品名和篇幅信息；“继续这一笔”；四步成果；少量变更提醒。保留既有书架行为，不另建指标中心。

“继续落笔”打开上次正文及其工作草稿，恢复章和光标。尚未开始写作时，主按钮指向最近未完成的具体阶段；已完成全书时改为“查看全稿”，仍可回到各步修改。

“查看审查”打开该成果最近报告，旧版也保留且明确标记。四步成果行进入对应页面；“打开织卷查看影响范围”打开受影响章节列表。所有数量来自持久化成果记录。

演示：共 36 章，7 章已有采用稿，第 7 章另有候选 v3。问心正典 v2 已采用；设定 18 项已采用，另有 2 项草稿；章概要已生成 16/36。S02/S11 展示这本书建书前的独立时间点；状态板 S10 展示其他状态，不能把全部画板当同一时刻数据库快照。

## 6. S02 问心

### 6.1 页面与内容

左侧构思对话，右侧故事正典。左侧已有的用户消息可编辑后重新发起，但保留旧轮次；输入框支持长文粘贴。模型回答结束不会自动采用正典。

正典字段：书名/类型/预计篇幅元信息预览，一句话故事，核心命题，主角与核心欲望，主要冲突，叙事视角与文风，故事边界/作者偏好，初始方向和待定项。右侧默认阅读，可点击“编辑”直接修改；长内容内部滚动，画板仅展示首屏。

未知问题可标待定。篇幅、结局等未定不阻止建书；书名允许先用可改的暂定名。书名实际来源为书籍元信息，正典预览不成为另一份独立书名字段。

### 6.2 操作

- 发送：仅调用 ask.main，更新问心会话；失败保留用户输入与重试入口。回答流式显示，“停止回答”停止当前请求并保留已有文字。
- 生成故事正典：右侧空态主按钮。读取目前对话与用户要求，产生首份候选，结果不自动建书。
- 更新正典 / 重新生成：读取当前候选与新增要求，默认保持手改，以新版本呈现；“整份重写”放入范围选择，需作者主动选择。
- 审查正典：保存当前快照，调用 ask.review，打开 S06。报告可以点击定位到正典小节。
- 采用正典并建书：仅首次显示；以 draftId 建立一本书，关联已有会话与正典版本，进入研墨空态。连续点击或请求超时重试返回同一本书。
- 已有书中的采用：文案“采用正典”，更新正式正典并提示下游依据变化；不再新建书，不自动生成设定。

审查维度：是否理解作者意图；核心矛盾和创作命题是否清晰；前提是否自相矛盾；篇幅与构想是否匹配；哪些待定问题可能影响后续。开放结局和作者主动保留的未知不能当作缺陷一律补全。

## 7. S03 研墨

### 7.1 设定目录与条目

目录由小说需要形成，默认可用世界与时代、人物、关系与势力、地点、规则与物品、历史与其他。现实题材不强制出现修炼体系。作者可以增减分类、条目，条目有稳定 ID，不用名称作为唯一身份。

进入后先读取已采用正典。无设定目录时显示“根据正典拟定设定目录”；输出目录候选及建议条目，作者可编辑后“生成全部设定”。目录不是新的强制审核关卡，允许在同一范围面板直接启动建议目录全部条目的生成。

条目显示来源正典版本、正式版与候选版、正文、关联条目和本次范围。人物卡包括身份、欲望、矛盾、人物弧线、关系、初始状态；其他类别根据内容用合适的小节。动态章节状态与开篇设定分开呈现。

### 7.2 操作与范围

“生成全部设定”打开范围面板：目标目录与条目数、生成缺失条目（默认）、重生成所选条目、整套重新生成。已有手改条目默认保留。按钮最终文案为“生成 20 项设定”或“补全剩余 8 项”，让范围可审阅。

“继续打磨”展开当前条目的要求输入，默认只改当前条目。选择多条时文案改为“打磨所选 N 项”。保持指定字段可在要求面板以复选项选择，也可自然语言补充。

“审查此条目”默认使用 ground.review；旁边范围菜单可选此分类 / 所选条目 / 全部设定。批量审查显示实际覆盖，失败项可单独重试，不能以部分成功标记整套完成。

“采用此版本”仅采用该条目。批量模式为“采用所选 N 项”，只处理候选并保留未选条目。右侧顶部两个版本标签打开版本切换/历史；条目标题可编辑名称，ID 和引用保持稳定。

添加空条目不调用模型；删除已有条目采用一次明确确认或可恢复归档，不能删除其历史及已生成章节。有关引用显示该条目已归档，作者可恢复。

审查维度：与正典一致，人物动机和弧线可用，世界规则自洽，关系与时间线不冲突，同名/重复/缺失条目，以及设定是否足够支撑规划。风格建议和确定冲突区分。

## 8. S04 织卷

### 8.1 大纲层级

左侧树必须包含全书大纲根节点、卷节点、章节点；PDF 展开的是第 7 章视图。选择根节点显示主线、支线、主题推进、主要转折与结局方向；选择卷显示卷目标、起止局面、关键转折、人物变化及章节范围；选择章显示完整章概要。

章概要至少包括章名、视角、时间/地点、登场人物、本章目标、冲突、转折、结尾衔接、关键伏笔、预计字数，以及引用的正典/设定。元信息区折叠显示依据，正文处只保留创作需要的字段。

根或卷节点允许编辑、审查和按意见调整；不能只有一棵章目录而没有可阅读的全书大纲。

### 8.2 全书与分批

“调整规划范围”打开侧面板：全书 / 本卷 / 自定义章范围，目标卷数与章数、预计章均字数、补充要求、缺失概要优先。默认继承正典篇幅，可改；改变目标数后已存在章不静默消失，移出本次目标的章仍保留并列在未纳入章节区。

选择全书 36 章时，任务依次得到全书结构、卷纲和 36 章概要；内部可以分批。页顶同时显示“已生成 16/36”“第17-20章生成中”。只有36个目标均有完整概要才显示这次范围生成完成；采用数另算。

不要求必须等全书生成结束才能写已准备好的章。后续范围可以继续补全。缺正典/设定时，范围面板提示当前缺项并提供去补齐与“使用现有资料继续”，后者记录本次输入情况。

### 8.3 操作

“审查本卷”使用 weave.review，菜单切换当前章/所选章/本卷/全书。独立审查完整性、因果与节奏；不能因生成只覆盖16章就只审16章却声称全书已审。

“重生成所选章”先显示章数、范围和保留项。默认保留未选章、已写正文和卷章 ID。修改涉及相邻章时将建议列出，由作者扩大范围后再运行；不暗中重写全书。

“采用并去落笔”采用当前选中候选的明确范围并进入所选章。当前章已经采用且无改动时文案改为“去落笔”，如PDF S04所示。采用概要不代表采用正文。

审查维度：大纲符合正典，设定能够支撑事件，人物因果连贯，各卷节奏与篇幅合理，章节目标有区别，转折有铺垫，伏笔有计划，用户指定的全章范围没有漏章。

## 9. S05 落笔

正文是主工作面。默认左侧章节目录、右侧编辑器；输入要求置于编辑器下方，历史对话在“创作记录”折叠区。沿用已有编辑、查找、字数统计、导出能力，不另造简陋纯文本框替换成熟编辑器。

进入未写章节时显示本章概要摘要、依据资料和“开始写本章”。点击使用 write.main，按前三步已采用资料生成正文候选。允许用户修改本章要求、目标字数、重点场景和保持的文风。

已有正文的输入框默认作用于当前章节；选中文字时出现“只改选中段落”，提交前显示范围。发送指令生成新候选，不把响应塞成大段聊天气泡。补写、续写、精修、整章重写放在范围/方式菜单中，默认精修当前范围。

“审查本章”只调用 write.review；若有报告，可再次审查或打开最近报告。选择段落时可审所选内容，报告注明局部覆盖。本章审查不能用全书通过之类措辞。

“采用此稿”更新本章正式正文及对应版本记录；界面显示“第 7 章已采用”。正文摘要、人物状态和伏笔变化归于同一正文版本。若这些辅助整理尚未就绪，提示“正文已采用，辅助资料待整理/整理失败”，提供重试整理。不能让落笔下一章静默读取另一版的旧摘要；作者可重试，或明确选择读取已采用正文继续。基础采用记录和文件写入失败时不声称正文已经采用。

新候选及其辅助产物只服务该候选；放弃候选不能推进正式人物状态。采用早期章节新稿后，后文保留，并标记相应连载状态待核对。历史恢复也经过采用记录，不能删除后续正文。

采用后在底部提供“写下一章”；没有下一章概要时可去织卷补齐或添加本章要求继续。审查可选，不能用未审查或评分不足拦住作者。

审查维度：与正典/设定/章概要和已采用前文的一致性，人物状态，时间和空间，伏笔/承诺，叙事视角、节奏、重复与文风。明确指出原文证据及参考来源，不把建议性的审美判断写成事实错误。

## 10. S06 通用审查侧栏

### 10.1 报告结构

顶部：阶段名 + 审查、成果名、被审版本、覆盖范围、实际审查模型、时间、“收起”。再往下是总体评语和意见列表。生成报告的状态占用本侧栏，正文保持可读；失败只显示本次审查失败。

每条意见包含：稳定 issueId、简短标题、程度（优先处理 / 可改善 / 风格建议）、目标小节/条目/章/段、原文证据、参考来源与版本、原因、修改建议。列表默认紧凑，点击展开证据和来源；右下固定显示选择数量、范围和修改按钮。

S06 演示第7章候选v3有3条意见，作者已选择2条。初次打开报告默认不选意见；“全选 / 清空”作用于当前报告可用意见。选择意见本身不等于接受结论或写入正文。

### 10.2 定位与修改

点击意见标题，编辑器滚到对应原文并短暂高亮；来自同一快照才能精确定位。优先稳定段落/小节 ID 加引用片段，无法可靠定位时降为条目或章级并说明“查看所在章节”，不能跳到猜测的行号。

底栏“按 2 条意见修改”调用该阶段 main，携带当前报告、所选意见、输入基线与范围。可以补充一句作者要求；没有选择时按钮不执行，旁边说明“先选择要处理的意见”。本次使用选中报告，不先偷偷重跑审查。

完成后进入 S07。生成方可以说明尝试处理了哪些意见，不能标记“独立复审通过”。再次审查新稿才得到新的独立报告；无自动循环。

报告对应旧稿时，顶部显示“这份报告基于v3，当前稿已变为v4”。主要动作“审查当前稿”，次要动作“沿用这些建议”：先明确显示当前v4为修改基线和旧意见，重新选择范围；结果从v4生成新候选，不能恢复v3覆盖手改。

历史报告通过版本菜单中的“审查记录”查看，按时间倒序；报告不可被下一次任务覆盖。无问题时写“本次未发现需修改的问题”，仍显示覆盖和版本，不给全书正确的保证。

报告失败重试只重试审查。部分批次成功时显示“已审查 X/Y 项”，其余失败项可重试；保留已获得报告，不能合成虚假的完整报告。

## 11. S07 版本比较与历史

进入比较时标题写清成果和范围。基线默认是生成前候选，另外注明当前正式版。例如已采用v2，按意见从候选v3生成v4：左侧v3，右侧v4，正式稿仍是v2。

两侧有版本名、变更小节和“新增 / 删除 / 替换 / 保留”文字标记。正常视口并排，窄窗上下排列。提供上一个/下一个差异及当前位置；S07展示差异1/2，第二处在第6段。长文使用同步滚动或按差异跳转，不截断成几张摘要卡。

页顶“尝试处理2条意见”属于本次生成说明。未勾选意见和未选范围仍可在比较中核查。若输出触及范围外内容，显示“有范围外变化”，默认仅应用选定范围的可用修改；作者可展开检查后显式采用更大范围，不能悄悄把整篇替换掉。

“保留原稿”回到修改前草稿v3，v4在版本历史仍可找到；“审查新稿”对v4调用对应review；“采用v4”采用指定版本并回到阶段页。比较页不再把“发送”设为主按钮。

版本历史显示编号、生成/手改/导入来源、时间、简短修改说明、是否采用、有无对应报告。查看历史只读；“以此继续编辑”复制为新草稿；“恢复采用此版”更新采用记录并提示影响。已采用版本不能因为清理候选被删掉。

## 12. S08/S09 八角色模型配置

### 12.1 固定四行两列

- 问心：ask.main（构思聊天与正典），ask.review（正典审查）。
- 研墨：ground.main（目录、设定、打磨），ground.review（设定审查）。
- 织卷：weave.main（全书、卷纲、章概要和改写），weave.review（规划审查）。
- 落笔：write.main（正文、按意见修改、摘要状态整理），write.review（正文审查）。

允许八项同模型，也允许全部不同。每项独立保存服务引用、模型、有效参数与角色说明。使用同一连接不意味着共享一份可变角色配置。复制后互不联动。

首期采用项目级八角色配置；书级覆盖与复杂多层继承后置。阶段页“调整模型”打开当前阶段主/审查角色选择，再编辑对应角色。保存不改变普通聊天的全局默认模型。

### 12.2 当前角色编辑

抽屉宽约590px，标题始终显示“落笔 · 审查”等角色。表单可滚动，底部固定取消、测试此配置、保存配置。

基本项：服务连接、模型、角色说明。模型列表加载失败时允许输入合法模型ID，并提示尚未验证。角色说明支持恢复默认，恢复只改当前表单，保存后才生效。

高级项折叠：流式输出开关、模型支持的温度/思考强度/输出预算/上下文预算等。按既有provider模型能力决定可用字段；不支持时不发送伪参数，不把旧全局maxTokens字段直接复活。接口类型等属于服务连接的字段在管理连接中修改；如果模型支持独立覆盖，用明确的高级字段表达。

未设置连接时显示“为落笔审查选择模型”，按钮进入“管理连接”。已有服务库负责名称、地址、接口类型、认证和可用模型等。角色表单仅引用服务；需要不同密钥时建立另一连接，成果/报告不保存密钥。

“测试此配置”测试当前未保存表单，显示测试中、可用、失败原因；它不生成小说、不保存表单。失败不必禁止保存有效格式的离线配置，保存后卡片显示“未验证/最近测试失败”。无连接或无模型等确实无法运行的缺项就地标明。

“保存配置”只保存标题指定角色。关闭未保存抽屉保留本次表单暂存，再打开可继续；明确点击取消恢复已保存值。改设置仅影响之后启动的任务，正在运行任务继续使用已记录配置快照。

### 12.3 填充与复制

首次迁移提供“从现有配置填充”，默认仅填八角色中缺失项，预览来源和目标数量；有旧覆盖项则优先映射对应职责，映射不明时展示供作者选择。已配置项不被默认覆盖。

“复制到其他角色…”打开目标复选列表，默认无选择。明确列出复制的是连接/模型/参数，角色说明默认不复制，避免把审稿说明粘成写作职责；作者可另选复制说明。最终按钮“复制到N个角色”是一次性操作，无需额外连环确认。

如果提供“仅本次使用其他模型”，使用临时标签并显示实际角色，运行结束后恢复角色默认，不暗中写回。首期可以只提供持久角色配置，临时覆盖不作为首轮验收阻碍。

## 13. S10 状态与提示文案

每种提示出现在它影响的区域，优先说明资料是否保留和下一步。

- 无正典：“还没有故事正典。先说一句你想写的故事，也可以粘贴已有构思。”动作开始对话/粘贴正典。
- 未配置：“问心的创作模型尚未配置。”动作配置问心模型，保留输入。
- 正在生成：“正在规划第17-20章，已完成16/36章。”动作暂停任务，不伪造剩余时间。
- 等待模型：“模型仍在响应，已接收内容会持续保存。”提供停止，不因暂时无token判定必然失败。
- 暂停：“已暂停，12/20项已保存。”动作继续剩余条目。
- 生成失败：“本批未完成，之前16章概要已保留。”动作重试未完成范围/查看原因。
- 审查失败：“这次审查没有完成。候选v3已保存，模型请求超时。”动作重试审查。
- 旧报告：“报告基于v3，当前草稿已更新。”动作审查当前稿/沿用这些建议。
- 上游改变：“本章依据有更新：记忆代价规则采用了新版本。”动作查看变化/确认仍适用。
- 保存失败：“草稿暂未保存到本地，编辑内容仍保留在当前窗口。”动作重试/复制内容。
- 采用失败：“采用未完成，当前正式版仍为v2，新候选v4已保留。”动作重试采用。
- 辅助整理失败：“正文已采用，摘要与状态整理未完成。”动作重试整理/查看已采用正文。
- 任务重连失败：“连接已断开，正在核对任务状态。”恢复后展示运行中或已中断；切勿直接发第二个同范围任务。
- 无审查意见：“本次未发现需修改的问题。”显示版本、范围、依据和审查时间。

工程详情和原始错误放在可展开“查看详情”；主文案不显示内部类名、HTTP堆栈或数据库名。明确的模型接口错误可给出可操作说明，例如检查连接/模型ID。

## 14. 输入、键盘与可访问性

Enter发送消息，Shift+Enter换行；中文输入法组合输入期间Enter只用于选词，不能发送。正文Enter始终换段。Ctrl/Cmd+S保存当前草稿；有需要时另提供“保存版本”，不劫持输入法和常用编辑快捷键。发送快捷键偏好沿用现有设置。

Tab顺序按页面阅读和操作顺序；图标按钮有中文可读名称，输入有label，禁用按钮附近说明原因。Esc收起临时侧栏并把焦点还给触发按钮；有未保存角色表单先保留暂存，不默默丢弃。覆盖式抽屉管理焦点，非覆盖式审查侧栏允许返回编辑器。

不靠颜色区分审查程度、版本、增删和进度；同时显示文字/符号。正文与交互文本需达到常规文本4.5:1对比度，焦点和关键非文本边界至少3:1；现有装饰边框无需全部加深，必要控件使用border-strong/ring。实施时对实际字体、混合底色和暗色状态检测，PDF肉眼检查不等于已完成可访问性测试。

动画仅用于150-200ms侧栏/状态过渡，尊重减少动态效果设置。流式输出不反复抢光标，不将每个token都播报给读屏；只播报任务开始、完成和关键失败。作者向上读时停止自动跟随，出现“回到最新内容”。

## 15. 给实现者的数据与事件约定

以下为设计所依赖的语义字段，不是已实现API，也不强制具体TypeScript写法。接口路径和组件拆分交由Grokbuild结合现有工程确定。

当前工作区需要：bookId或draftId、stage、selectedArtifactId、所选条目/卷/章/段范围、当前工作草稿revision、candidateVersion、adoptedVersion、保存状态、当前runId与任务状态、生成覆盖数和采用覆盖数、依赖待核对记录。

不可变成果需要：artifactId、stage、scope、version、parentVersion、来源、正文/文件引用、inputRefs（资料ID与版本）、创建时间、关联运行。集合操作必须保留每个条目版本，不能用一个总版本假装所有条目一齐更新。

报告需要：reportId、stage、targetRefs（被审成果版本集合）、覆盖范围、inputRefs、actualReviewModel、时间、总体评语、issues；每条issue包含ID、程度、锚点、原文证据、参考依据、原因、建议和建议修改范围。

重生成请求需要：阶段、基线成果版本、用户要求、scope、需要保留的内容；按报告修改额外带reportId和selectedIssueIds。只传问题字符串不足以保证用的是用户刚看过的报告。

模型配置需要：固定roleId、serviceRef、modelId、支持且生效的参数、stream、角色说明及其版本。运行记录需要实际解析后的配置快照，不能事后根据当前设置反推当时模型。

事件至少覆盖开始、进度、部分成果保存、任务完成/暂停/失败、报告就绪、采用完成、依赖变化。所有异步结果带runId和目标标识；前端只更新对应作品/成果，避免切书后旧流式结果写进新书界面。保存回执决定已保存状态。

生成、审查、按意见修改、采用是四个独立操作。聊天只产生会话，除非用户触发生成/更新成果。审查不写正式小说文件；生成不暗中调用审查；点击采用才更换正式资料。

## 16. 兼容、范围与实施顺序

在原仓库页面演进：问心对应BookAskPage/ChatPage；研墨对应BookGround；织卷对应OutlineWorkspace；落笔对应BookDetail/ChapterReader；模型配置接入既有服务库。重构规划已给出核实过的调用链、风险与代码落点，本文件不另起新架构。

旧书首次进入显示“已载入现有作品资料”，从已有正式文件形成可读的兼容成果记录；无历史报告就显示未审查/历史记录缺失，不伪造通过。已写正文、版本历史和会话保留；接入新四步失败时仍能阅读旧书并重试接入。

正典权威来源、角色卡、规则卡与兼容story_frame的关系按配套重构规划第6节执行。页面从统一读取层获得数据，不各自猜来源。桌面端口由壳控制，项目根目录显式传入，继续使用现有文件存储，不恢复旧Next.js/IndexedDB方案。

实施顺序：先M0角色配置/版本/报告基础及公共组件，再M1问心完整闭环，再M2研墨、M3织卷全章覆盖、M4落笔，最后M5旧书兼容与全流程打磨。每期都应跑通真实数据链路，不能完成全部静态页后宣称多Agent已接通。

首轮保留：八角色配置、四步成果、主动审查、按选中意见重生成、比较采用、保存与任务恢复、全部章概要范围、暗色和常用桌面窄窗。后置：书级模型覆盖、复杂条件自动编排、多人协作、手机专用界面、全书逐句批量审稿。
